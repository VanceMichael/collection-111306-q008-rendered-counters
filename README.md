# 样本页生成文字与计数标签的忠实采集

纸质样册改成在线排版以后，章节号、风险标识和部分单位是样式生成的，原来的正文爬虫把“不得混用”前的警示标记漏掉了。这里在现有资料预览工具与本地供方模拟服务之上，增加按**实际呈现**组织文字的样册采集与引用回查能力，便于离线开发和复查领取行为。

## 当前能力

`npm run demo` 从实际本地资料源获取一次预览，将结果写入 `var/captures.json`，并打印接收文件和本次可见内容。它还不是业务批量接收器。`src/domain.mjs` 保留已有领域预览函数；`src/store.mjs` 提供带完整性校验的单进程顺序接收文件，不是跨进程事务数据库。

新增的样册采集（`src/catalog.mjs`、`src/collector.mjs`、`src/evidence.mjs`）在真实 Chromium 中按呈现组织证据，而不是拼接 `textContent`：

- **可访问正文、生成文字与计数标签分别留证**：DOM 文本与 `::before`/`::after` 生成文字分开记录。计数器的渲染编号取自 CDP 无障碍树（其中 `counter()` 已解析为真实数字，例如屏幕版 `3.`、打印版 `10.`）；`getComputedStyle(...).content` 只保留未解析表达式作为对照，绝不把表达式字符串当编号。旧爬虫漏掉的 `⚠ 不得混用：` 警示标记由此被采集到。
- **引用关系按身份锚点回查**：引用只以持久目标 `id` 解析，编号文字仅作为当次呈现的冻结证据。切换媒体样式、插入前置章节导致重编号后，旧引用仍查回原目标，并如实报告目标已重编号、路径已移动，旧编号不会被悄悄解释成新目标。
- **每种呈现独立成证**：屏幕版与打印版分别采集，各自带 `captureId`、媒体、样式版本、样式表签名与 DOM 签名；一个版本的编号不会挂到另一个版本的段落上。
- **知道自己读的是哪版样式**：迟到样式通过 `MutationObserver` 记录样式变更事件，重采时样式签名变化可被独立观察；字体状态同样写入证据。浏览器对已建计数器可能不重算，采集如实记录渲染结果，不臆测“应有”的编号。
- **取舍显式说明**：`aria-hidden` 装饰图形（`◆`）不会被凭空转成正文文字；`hidden` 隐藏段落与仅供读屏（sr-only）内容进入 `exclusions`，保留来源文字与取舍原因，不并入视觉正文。


## 运行

容器内固定 Playwright 1.56.1 与匹配的 Chromium。浏览器只访问本进程启动的回环资料源，不需要访问外部门户。

```sh
npm ci
npx playwright install chromium
npm run build
npm test
npm run demo
```

推荐使用固定镜像构建，首次构建会安装锁文件中的依赖；运行时不需联网。

```sh
docker build -t plant-rendered-counters .
docker run --rm --network none --ipc=host plant-rendered-counters npm test
docker run --rm --network none --ipc=host plant-rendered-counters npm run demo
```

开发时 `npm start` 打印本地源地址；设置 `PORT` 可指定监听端口，未设置时自动分配回环端口。浏览器页面或 HTTP 接口可直接查看。`CAPTURE_PATH` 可改变接收文件路径。重复运行预览追加记录；删除 `var` 可从空接收状态开始。

## 模块

- `src/source.mjs`：该业务的本地资料源与演示控制，独立于待扩展的接收行为。
- `src/domain.mjs`：现有原始资料预览和领域数据结构。
- `src/evidence.mjs`：纯领域逻辑——呈现上下文、content 表达式分词、计数器渲染值对齐、引用严格回查与跨版解释。
- `src/collector.mjs`：浏览器采集器。页面内检查器负责身份/结构/取舍，CDP 无障碍树负责伪元素与计数器的实际渲染文字。
- `src/catalog.mjs`：在同一页面上编排屏幕版/打印版多次采集，组装样册证据并提供 `lookup`/`explainCurrent` 回查。
- `src/preview.mjs`：读取、预览及持久化的一次运行入口（含切换媒体、插入章节、迟到样式与引用回查演示）。
- `fixtures/source.json` 与 `fixtures/controls.json`：本地供方资料及可切换情形。
- `docs/source.md`：接口和来源约定。
- `test`：现有预览、源端特殊情形、接收文件完整性测试，以及采集与引用回查测试（`evidence.test.mjs`、`catalog.test.mjs`）。

## 业务核对

以下情况由接收器在真实浏览器中独立观察，而不仅是源端能够制造这些情况（对应测试见 `test/catalog.test.mjs`）：

- 嵌套计数及自定义起值：计数器真值经无障碍树采集并与表达式对齐。
- 屏幕版和打印版编号不同：同一 `id` 目标在两次采集中分别保留 `3.` 与 `10.` 证据，不跨版挂载。
- 迟到样式引发重编号：样式版本、样式表签名与样式变更事件分别留证，采集明确知道自己读的是哪版样式。
- 装饰图形不编造文字：`aria-hidden` 图形进入排除清单而非正文。
- 旧引用仍能查回原目标：回查只认目标 `id`，并报告重编号与路径移动，旧编号不被复用为新目标。

测试只验证现有工具与源端行为，不代表新增业务能力已经交付。新增行为在独立模块扩展，保留原有预览调用；禁止把源端模拟器改成替接收器完成核对。

## 短时操作演示

从空 `var` 运行 `npm run demo`，展示本次真实读取和接收路径；再运行 `npm test` 查看本地源边界与接收文件检查。固定环境中的这两步应在 90 秒内完成。业务功能扩展后同步更新该入口，使其展示实际完成情况、未确认部分及原因，不回放旧日志，不以源端控制操作代替接收结果。
